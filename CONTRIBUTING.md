## How Can I Contribute?

### 🐛 Reporting Bugs / Errors

- Open a [GitHub Issue](https://github.com/vivekpandey76/mongodb-notes/issues/new)
- Use a **clear, descriptive title**
- Mention the **Part number** and the incorrect/outdated content
- Suggest a correction if you have one

### 💡 Suggesting Enhancements

- Open an issue with the label `enhancement`
- Describe the new topic, example, or improvement you'd like to see
- Explain **why** it would benefit learners

### 📝 Submitting a Pull Request

- Fix a typo or factual error
- Add a missing code example
- Improve explanation clarity
- Add a new sub-topic within an existing Part

## Getting Started

1. **Fork** this repository
2. **Clone** your fork:
   ```bash
   git clone https://github.com/<your-username>/mongodb-notes.git
   cd mongodb-notes
   ```
3. **Create a branch** for your change:
   ```bash
   git checkout -b fix/typo-in-part-17
   # or
   git checkout -b feature/add-part-28-notes
   ```
4. Make your changes
5. **Commit** with a clear message:
   ```bash
   git commit -m "fix: correct $lookup example in Part 19"
   ```
6. **Push** and open a Pull Request against the `main` branch

## Style Guide

To keep the notes consistent:

- **Headings** — Use `##` for sections, `###` for subsections
- **Code blocks** — Always specify the language (` ```js `, ` ```bash `, etc.)
- **Operators / keywords** — Wrap in backticks: `$match`, `findOne()`, `ObjectId`
- **File naming** — Follow the existing pattern: `Part X: Topic Name.md`
- **Tone** — Clear, friendly, and concise — as if teaching a peer developer

---

## Pull Request Process

1. Ensure your changes are limited to the scope of your branch
2. Link any related issue in the PR description using `Closes #<issue-number>`
3. A maintainer will review and merge or request changes within a few days
4. Once merged, your contribution will be credited 🎉
